# Интеграция 1С УНФ 3.0 → Единая база (gbsale.ru)

Файлы:
- `ЕдинаяБазаGB_модуль.bsl` — код общего модуля `ЕдинаяБазаGB`.
- Этот файл — инструкция по созданию регистра очереди и регламентного задания.

## Что делает интеграция

1С **не ждёт** ответа от сайта. Подписки на события (запись номенклатуры, проведение документов) мгновенно пишут данные в регистр сведений «Очередь обмена». Отправку на `gbsale.ru` выполняет регламентное задание раз в минуту.

## Шаг 1. Создать регистр сведений

В конфигураторе, внутри расширения `GadgetBarIntegration`:

**Действия → Добавить → Регистр сведений**  
Имя: `GadgetBar_ОчередьОбмена`

### Измерения

| Имя | Тип | Длина | Примечание |
|-----|-----|-------|------------|
| `Endpoint` | Строка | 100 | `/api/1c/products`, `/api/1c/prices`, `/api/1c/stocks` |
| `Идентификатор` | Уникальный идентификатор | — | ключ записи |

### Ресурсы

| Имя | Тип | Длина/тип | Примечание |
|-----|-----|-----------|------------|
| `Payload` | Строка | без ограничения | JSON с данными |
| `ДатаСобытия` | Дата | — | когда произошло событие |
| `Обработано` | Булево | — | `Ложь` → `Истина` после успешной отправки |
| `ДатаОбработки` | Дата | — | когда отправили |
| `Ошибка` | Строка | 1000 | текст ошибки, если не отправилось |
| `Попыток` | Число | 2 | счётчик попыток, после 5 записи игнорируются |

### Периодичность

Установить **«Непериодический»**.

### Режим записи

Оставить **«Независимый»**.

## Шаг 2. Создать регламентное задание

**Действия → Добавить → Регламентное задание**

| Свойство | Значение |
|----------|----------|
| Имя | `GadgetBar_ВыгрузкаВЕдинуюБазу` |
| Метод | `ЕдинаяБазаGB.ОбработатьОчередь` |
| Пользователь | любой с правами на регистр и HTTP |
| Расписание | каждые 60 секунд (или раз в минуту) |

## Шаг 3. Добавить общий модуль

Если ещё не создан:

**Действия → Добавить → Общий модуль**

| Свойство | Значение |
|----------|----------|
| Имя | `ЕдинаяБазаGB` |
| Клиент (управляемое приложение) | да |
| Сервер | да |
| Внешнее соединение | да |
| Вызов сервера | да |

Скопируйте весь текст из `ЕдинаяБазаGB_модуль.bsl` в этот модуль.

## Шаг 4. Подписки на события

Создайте подписки (или обновите существующие):

### 1. `GadgetBar_ПриЗаписиНоменклатуры`
- Событие: **ПриЗаписи**
- Объект: **Справочник.Номенклатура**
- Обработчик: **ЕдинаяБазаGB.ПриЗаписиНоменклатуры**

### 2. `GadgetBar_ПриПроведенииУстановкиЦен`
- Событие: **ОбработкаПроведения**
- Объект: **Документ.УстановкаЦенНоменклатуры**
- Обработчик: **ЕдинаяБазаGB.ПриПроведенииУстановкиЦен**

### 3–6. Документы остатков
Для каждого документа создайте подписку на событие **ОбработкаПроведения** с обработчиком **ЕдинаяБазаGB.ПриПроведенииДокументаОстатков**:
- `GadgetBar_ПриПроведенииПриходнойНакладной` → **Документ.ПриходнаяНакладная**
- `GadgetBar_ПриПроведенииРасходнойНакладной` → **Документ.РасходнаяНакладная**
- `GadgetBar_ПриПроведенииПеремещенияЗапасов` → **Документ.ПеремещениеЗапасов**
- `GadgetBar_ПриПроведенииСборкиЗапасов` → **Документ.СборкаЗапасов**

## Шаг 5. Обновить базу и проверить

1. Нажмите **F7** (обновить конфигурацию базы данных).
2. Откройте журнал регистрации, фильтр по событию **GadgetBar.ЕдинаяБаза** — туда пишутся ошибки.
3. Проведите документ **Установка цен номенклатуры** — в регистре «Очередь обмена» должны появиться записи, которые через минуту отправятся на сайт.
4. Проверьте результат на сайте или по журналу регистрации.

## Возможные доработки под конкретную базу

Если в документе «Установка цен номенклатуры» имена реквизитов отличаются от типовых (`Цена`, `ВидЦен`, `Количество`), поправьте их в процедурах `ПриПроведенииУстановкиЦен` и `ПриПроведенииДокументаОстатков`.
